#### Goals
1. Compare and contrast different cache organizations (<span style="background:#b1ffff">direct mapped, set associative, fully associative</span>) across several dimensions (e.g., <span style="background:#b1ffff">area overhead, access latency, miss ratios</span>)
2. Compare and contrast different cache partitions (e.g., <span style="background:#b1ffff">harvard architectures, multi-level caches</span>) across several dimensions (e.g., <span style="background:#b1ffff">area overhead, performance, inclusion vs. exclusion</span>)

# Cache hierarchy

- number of blocks

multiple address can map to the same set
- we need tag and valid bit=1 for a hit

compulsory misses?
conflict miss

TLB, VPN, PFN

<span style="background:#b1ffff">Example:</span> what is the CPI after adding a “real” instruction cache if 30% of all
instructions access the data cache?
- CPI = CPIbase + CPI penalty = 1.3 + (0.05)(100) + (0.3)(0.15)(100) = 10.8

cache size increase
- miss rates decrease
- access latency increases

<span style="background:#b1ffff">Example:</span> AMAT with L1 and L2 caches
- AMAT = 1 + (1-0.95)(10+0.2(100)) = 2.5
- 100 x (1-0.95) x 0.2 = 10

memory coherence for single core
- load instruction returns the value of the previous store (program order) to the same address

memory inclusion
- L1 and L2 are inclusive if every cached item in L1 is also in L2
	- helps maintain coherence
	- Also helps in multi-core cache hierarchies

memory exclusion
- L1 and L2 are exclusive if none of the cached items in L1 are in L2 and vice versa
	- Now, the total cache capacity is the sum of L1 and L2's size
