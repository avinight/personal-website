### Goals
1. Define memory consistency and related terms (like program order, memory order, etc.)
2. Differentiate between memory consistency and cache coherence
3. Infer execution paths from short code snippets and justify whether they adhere to a memory consistency model

How might a core reorder memory accesses?
- Store-store reordering
	- Caused by, e.g., core has a write buffer, but the policy is not FIFO
	- e.g., first store is a miss, second store is a hit
- Load-load reordering
	- Instructions may be executed out-of-order (though they commit in-order)
- Load-store reordering
	- Can reorder loads and stores if they don’t share the same address
- Store-load reordering
	- Caused by, e.g., core has a write buffer

A non-blocking cache
- The core-cache interface does not block the core on a miss
- The miss is stored in a miss-status-handling-register (MSHR)
- The miss is handled by the cache-memory interface
- Multiple loads/stores may be overlapping in time

A cache hierarchy
- Cache hierarchies reduce the average miss penalty
- Buffers placed between components manage the traffic between them
- In-bound messages (e.g., from the network) may take a long time to reach the core
- Similar for out-bound messages

The interconnection network
- Shared bus
	- Connect multiple components (caches, memory) for broadcast-based messages
	- Split-transaction bus allows multiple transactions to be in progress at a time
- Scalable interconnect
	- Create point-to-point connections between components (caches, memory)
	- Messages can be routed from one component to another through the network
	- Naturally supports multiple messages
		- But messages may be received out-of-order, depending on the route taken

From chaos to order
- Optimizing architectural components for performance leads to chaos
	- Requests for, and responses to, data can seemingly happen at any time
- How do we ensure programs continue to work correctly?
	- We need a definition of correct behaviour before we can implement it
	- This definition is part of the ISA

# Fundamental concepts

What is memory consistency?
- Defines the correctness of shared memory behaviour in terms of memory reads (loads) and writes (stores)
	- Part of the architectural specification
- Our definition is (will be) agnostic of implementation details
	- e.g., cache organization
	- e.g., coherence protocol
- Other names: consistency, memory model, memory consistency model

Why is memory consistency hard?
- Single-threaded model
	- Given an input, execution of the thread leads to one well-defined (correct) output
- Multi-threaded (shared memory) model
	- The ISA allows threads to run concurrently, leading to many possible executions
	- Consistency defines which executions are correct and which are incorrect

What is (program, memory) order?
- Program order (<p) of X
	- Order of operations for a core
	- op1 <p op2 ⇒ op1 precedes op2 in a core’s program order
- Memory order
	- Order of all operations
	- Total order
	- op1 <m op2 ⇒ op1 precedes op2 in memory order

What is cache coherence-
- A part of the memory consistency model
	- A coherence protocol supports a consistency model
- Coherence: make it appear as if there is only one value in the system
	- i.e., make the cache hierarchy invisible to the programmer
	- How? Propagate writes to other caches when necessary
- Coherence presents an abstraction of the memory system to the core
- The single-writer-multiple-reader (SWMR) invariant
- Definition: Given a memory location, there is either:
	- 1 core that can write (or read) it, or
	- 0 or more cores that may read it
- The data-value invariant
- Definition: Given a memory location, its value at the start of an epoch equals the value from its last read-write epoch
- The single-writer-multiple-reader (SWMR) invariant
	- Given a memory location, there is either: 1 core that can write (or read) it, or 0 or more cores that may read it
- The data-value invariant
	- Given a memory location, its value at the start of an epoch equals the value from its last read-write epoch
What is an epoch?
- Divide the lifetime of a memory location into epochs
- During an epoch, either
	- 1 core has read-write access
	- 0 or more cores have read-only access
