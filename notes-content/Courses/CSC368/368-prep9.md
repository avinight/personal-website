### Goals
1. Sketch a cache coherent NUMA organization and describe the different components (nodes, cores, caches, etc.) and how they are connected
2. Enumerate the steps needed to keep caches coherent for read requests and write requests for different cases (e.g., dirty/clean, number of sharers) assuming directories and an MSI protocol
## Directory Protocols

How do we scale to many cores?

Limitations of a shared bus
- Number of connections is limited
- Bandwidth is limited; bus saturates quickly
- Messages are sent to everyone, even if only a (small) subset have cached copies
	- Waste of bandwidth

A scalable organization
- Interconnection network bandwidth that scales with number of cores (nodes)
- Distribute memory to exploit locality
- Messages are only exchanged by those needed for the transaction

Example: A cache coherent NUMA
• Each node contains
• Core (C)
• Cache ($)
• Memory module (M)
• Shared cache is banked
• Distributes data across nodes
• The network is “scalable”
• Where is the cache coherence?
• Each memory module has a directory

What is a directory?
A directory is made up of directory
entries
• Directory entries track the sharing
data for a block
• Dirty bit
• Presence flag vector (PFV) tracks
which nodes have a copy of the block
• e.g., 16 nodes = 16-bit PFV
• Each bit corresponds to a node
• Bit indicates whether node has a
copy

What is a local, remote, home node?
Local (L)
• Initiates the request
• Home (H)
• Contains the directory information
• Remote (R)
• Participating in the transaction (0 or
more nodes)

How does a read request work?
The block is clean
1. Local node sends request to home
node
2. Home node responds with data and
updates PFV

The block is dirty
1. Local node sends request to home
node
2. Home node forward the request to the
remote node
3. Remote node sends data to home
node
4. Home node updates memory copy,
directory information
5. Home node sends data to local node

How does a write request work?
No other cached copies exist
1. Local node sends upgrade request to
home node
2. Home node updates dirty bit and
sends acknowledgement to local node

Other cached copies (sharers) exist
1. Local node sends upgrade request to
home node
2. Home node sends invalidation requests
to remote node(s)
3. Home node receives invalidation
acknowledgements from remote
node(s)
4. Home node updates directory
information and sends upgrade
acknowledgement to local node

Scalable cache coherence with directories
Summary
• Nodes are connected to a scalable
interconnect
• Directories track whether data is dirty,
and which nodes have a cached copy
• Messages are sent only to nodes
involved in a transaction
• Can adapt protocols, like MSI, to use a
directory instead of snooping

Challenges
• Directories may be involved in
replacements (e.g., eviction of clean
block)
• Need to handle race conditions
• Only one request/block at a time
• Reducing overhead
• PFV size grows linearly with number of
nodes
