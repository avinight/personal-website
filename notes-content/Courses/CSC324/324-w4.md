> [!NOTE] 
> We are going to investigate the difference between call-by-value and call-
> by-name semantics.
> Consider the following expression:
> ```
> (λx. λy. y) ((λz. z z) (λz. z z)) (λw. w)
> ```
> You are going to evaluate the two expressions using call-by-value and
> call-by-name semantics.

Call-by-value
```
((λz. z z) (λz. z z)) -> ((λz. z z) (λz. z z)) -- E-AppAbs
(λx. λy. y) ((λz. z z) (λz. z z)) -> (λy. y) -- E-AppAbs
(λx. λy. y) ((λz. z z) (λz. z z)) (λw. w) -> ((λy. y) (λw. w)) -- E-App1
(λx. λy. y) ((λz. z z) (λz. z z)) (λw. w) -> (λw. w) 
```

Call-by-name
```
(λx. λy. y) ((λz. z z) (λz. z z)) -> (λy. y) -- E-AppAbs2
(λx. λy. y) ((λz. z z) (λz. z z)) (λw. w) -> ((λy. y) (λw. w)) -- E-App1
(λx. λy. y) ((λz. z z) (λz. z z)) (λw. w) -> (λw. w)
```


What was the difference between the two evaluation strategies?
- Call-by-value evaluates the arguments first
- Call-by-name evaluates the function first
- call-by-name doesn't have E-App2.
- CBV substitution applies only to values

A string of digits may be interpreted in two ways:
- The most significant digit is to the left, or
- The most significant digit is to the right.
Suppose you are given a list of bits, write two functions that interpret the list of digits into an integer:
- `bigEndian :: [Bit] -> Int` chooses the left-most digit to be the most significant, and
- `smallEndian :: [Bit] -> Int` chooses the right-most digit to be the most significant.
Use foldl and foldr.

```Haskell
data Bit = Zero | One

bitToInt :: Bit -> Int
bitToInt Zero = 0
bitToInt One = 1

bigEndian, smallEndian :: [Bit] -> Int
bigEndian digits = foldl (\acc x -> acc * 2 + (bitToInt x)) 0 digits
smallEndian digits = foldr (\x acc -> acc * 2 + (bitToInt x)) 0 digits
```
