**Model parameters** are the internal variables learned by the model during training (e.g., weights in a neural network, coefficients in linear regression). They are adjusted to fit the training data.

**Hyperparameters** are external settings chosen before training (e.g., learning rate, number of layers, batch size). They control the training process and model structure but are not learned from the data. Hyperparameters are usually tuned using validation data. (e.g. k is a hyperparameter in k-NN)

What are training, validation, and test sets?
- **Training set** is used to learn model parameters.
- **Validation set** is used to tune hyperparameters and choose between models.
- **Test set** is used only once at the end to evaluate how well our model generalizes to unseen data.

Why Split the Data? What do we need to do with our data?
- Train a model.

- Evaluate our model on unseen data

How does varying k affect kNN’s behaviour?

Varying **k** in kNN affects its bias-variance tradeoff:
- **Small k** (e.g., k=1): The model is sensitive to noise, leading to **overfitting**. (high variance)
- **Large k**: The model becomes too smooth, possibly ignoring local patterns, leading to **underfitting** (high bias)
A common heuristic is to choose **k < sqrt(N)**, where N is the number of training samples, to balance bias and variance. Proper selection of k is crucial for optimal performance.

> [!question] 
> What is the purpose of the training, validation and test sets? Consider the kNN algorithm.
> What do you expect the training, validation and test errors to look like if k is too small?
> What about when k is too large?

**Purpose of sets:**
- **Training set:** Used to fit the kNN model (store labeled data).
- **Validation set:** Used to tune hyperparameters (e.g., k) and select the best model.
- **Test set:** Used to estimate the final, unbiased performance of the model.
**If k is too small (e.g., k=1):**
- **Training error:** Very low (often 0%), as each point is its own neighbor.
- **Validation/test error:** High, due to overfitting and sensitivity to noise.

**If k is too large:**
- **Training error:** High, as predictions are averaged over many points, possibly including those from other classes.
- **Validation/test error:** Also high, due to underfitting and loss of local structure.

**Summary:**  
Both very small and very large k lead to poor generalization; validation error helps find a good balance.

> [!question] 
> Consider applying the kNN algorithm to a data set. Suppose we split our data into training,
> validation, and test sets. Assume that we will try k = 1, 3, 5. Explain in detail what we
> need to do for each data set.

Here’s what you need to do for each data set:

**Training set:**
- Store the labeled data points.
- Use these points as the reference for kNN predictions.

**Validation set:**
- For each value of k (1, 3, 5), use the training set to make predictions on the validation set.
- Compute the validation error for each k. (or validation accuracy)
- Select the value of k that gives the lowest validation error. (or highest validation accuracy)

**Test set:**
- Using the best k (chosen from validation), use the training set to make predictions on the test set.
- Compute and report the test error as the final unbiased estimate of model performance.

**Summary:**
- Training set: store data.
- Validation set: tune k.
- Test set: evaluate final performance.

> [!question] 
> Why does the kNN algorithm suffer from the curse of dimensionality? Explain as succinctly
> as possible.

The kNN algorithm suffers from the curse of dimensionality because, in high-dimensional spaces, data points become uniformly distant from each other, making it hard to distinguish between close and far neighbors. This reduces the effectiveness of distance-based classification.

> [!question] 
> Why is it a good idea to normalize the features in the data set before training a kNN
> model?

It is a good idea to normalize features before training a kNN model because kNN relies on distance calculations. Without normalization, features with larger scales can dominate the distance metric, leading to biased and inaccurate neighbor selection. Normalization ensures all features contribute equally.

> [!question] 
> During the lecture, we saw that when we use the Euclidean distance measure, kNN’s
> predictions change when we change the scales of the features. Is this claim still true when
> we use a different distance measure, e.g., the cosine similarity?
> If your answer is “yes”, justify your answer using an example (e.g. create a data set and
> demonstrate the difference.)
> If your answer is “no”, prove it.

**No, this claim is not true for cosine similarity.**

**Proof:**  
Cosine similarity measures the angle between vectors, not their magnitude. Scaling a feature (multiplying by a constant) does not change the direction of the vector, only its length. Since cosine similarity is only concerned with direction, changing the scale of features does **not** affect the similarity or kNN predictions.

**Mathematically:**  
For any vector ( x ) and scalar ( c > 0 ),  $$ \text{cosine\_similarity}(cx, y) = \frac{(cx) \cdot y}{|cx| |y|} = \frac{c(x \cdot y)}{c|x||y|} = \frac{x \cdot y}{|x||y|} $$ So, the similarity remains unchanged.

**Conclusion:**  
Changing feature scales does **not** affect kNN predictions when using cosine similarity.

> [!question] 
> Your friend Yumeng says that “kNN does not require any training.” Is Yumeng correct?
> Justify your answer.

Yes, Yumeng is correct.  
kNN is a **non-parametric, instance-based** algorithm that does not require explicit training. It simply stores the labeled data and makes predictions by comparing new inputs to the stored examples using a distance metric. There is no model fitting or parameter learning phase.

> [!question] 
> What is the computational complexity of kNN, i.e. how much computation does kNN need
> to perform to make each prediction?

The computational complexity of kNN for each prediction is $\mathcal{O}(Nd)$, where **N** is the number of training samples and **d** is the number of features.  
This is because kNN computes the distance between the query point and every training point, then selects the k nearest neighbours.

> [!question] 
> What is the space complexity of kNN, i.e. how much storage does the model require?

The space complexity of kNN is $\mathcal{O}(Nd)$, where **N** is the number of training samples and **d** is the number of features.  
This is because kNN stores the entire training dataset in memory for prediction.
