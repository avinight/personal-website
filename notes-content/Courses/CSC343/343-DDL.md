For DDL (Attempting to define a foreign key that could fail):
- Referenced column doesn't exist
- Referenced column isn't unique
- Local column doesn't exist
- Mismatched data types
- Referencing multiple columns, but wrong number of columns
- Self-referencing foreign key but out of order
- Existing data violates the foreign key (insert/update)
- Circular dependencies on creation (foreign reference each other)
- Wrong schema, missing table
- ### Bonus: ❗Not a failure, but a **trap**
	- If you **reference a column that has a unique constraint on a nullable column**, the FK will still work, but:
	- The referenced table can have **one `NULL`**, and the FK won’t match it
	- If you're expecting full coverage (i.e. "every value in parent exists"), this may give a false sense of safety
