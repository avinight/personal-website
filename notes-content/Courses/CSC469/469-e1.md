Q5. From dmesg, we can see that Linux 6.7 detects it is running on top of a VM by outputting `Hypervisor detected: KVM`. KVM is the kernel virtual machine. We can trace this to the `arch/x86/kernel/cpu/hypervisor.c` and `arch/x86/include/asm/hypervisor.h` files. The `init_hypervisor_platform` method calls `detect_hypervisor_vendor`, which is responsible for iterating over a list of known hypervisors of type `x86_hypervisor_type`. We see for KVM, `x86_hyper_kvm` uses the `kpu_cpuid_base()` detection method. The cpuid instruction `boot_cpu_has(X86_FEATURE_HYPERVISOR)` is checked and `cpuid` compares the signature `"KVMKVMKVM\0\0\0"` defined in `kvm_para.h` with every possible hypervisor cpuid and returns the base. 
Q6. When insmod is called, it triggers the kernel module loader and calls `parse_args` which is implemented in the `kernel/params.c` file. `parse_args` loops through each command line argument and calls parse_one which matches the argument provided at the insmod call to the name defined in the module. It then executes the type specific `.set` operation such as `param_set_bool`, `param_set_charp` for our examples. This initialization occurs before `module_init` is called.
