I think abstraction is the most prevalent in Unix.

The guiding design philosophy of the exokernel was minimality taken to the extreme and the end-to-end principle, so that there are fewest hardware abstractions as possible. They separated the concept of protection from abstraction and management

The exokernel design philosophy was to eliminate OS abstractions, separating protection of resources from abstraction and management. i.e., securely multiplex bare hardware among user processes, imposing no OS abstractions on the end applications. The end-to-end argument says functionality should not be implemented in lower layers unless it can be completely and correctly implemented there. Since some resource management decisions can be improved with the help of the application, or specialized for certain applications, they should not be implemented in the kernel, but rather left to the applications.

OS extensions are supported by Mach through its 4 basic abstractions and OS personalities. Since Mach is a microkernel, it is much easier to add new functionality.

They are supported by linux through loadable kernel modules / eBPF. Because linux is a monolith, kernel modules are hard to verify for correctness and may not be safe as boundaries between modules are often blurry.

In Mach, extensions are provided by new user-level servers. In Linux, extensions are provided by kernel modules. Mach’s primary advantage is safety - extension code runs at user-level and is isolated from the microkernel and other servers. Linux’s primary advantage is performance - modules execute
in the kernel address space and can directly invoke other kernel functions or read/write kernel data structures.

- Lock acquisition is expensive because of wasted CPU cycles on memory barriers and instructions that block memory
	- Requires some atomic memory operation, so it will happen at memory speed and not at CPU or cache speed. As CPUs have become faster relative to memory access time, the cost of these atomic memory operations has increased. 
	- Requires explicit fences or barriers to prevent memory operations from being re-ordered across the lock, which stalls processor pipelines and prevents many optimizations. Processor pipelines have become deeper and rely more on out-of-order execution to keep them filled, so the barriers become more costly.

- Ticket locks make no progress (convoy effect) FCFS vs FIFO
